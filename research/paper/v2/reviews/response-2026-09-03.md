## W1 — single-driver, single-trial LLM record

- Added a repeated-trial measurement (`qa/verification/repeated_trials.py`,
  results in `research/experiments/results/dw-repeated-trials.json`): k=5
  independent trials of the constrained pipeline on the pinned DesignWare
  extraction, per backend (harness, bare-metal, Linux), measuring the SAME
  candidate at three stages — raw first pass (compile-repair disabled),
  post compile-repair (the pipeline's default bounded budget), post
  receipt-repair (the bounded `repair_lowering` protocol, up to six rounds,
  with brace/comment/re-compilation guards) — with the gate's own check
  states recorded per stage. Reported in the evaluation's repeated-trials
  paragraph. The Rust backend remains single-trial; this is stated.
- Measured outcome (temperature 0, same endpoint): no trial reaches
  acceptance at any stage. Harness 0/5 compiles even post compile-repair;
  bare-metal compiles post-repair in 3/5 but receipt accounting stays
  incomplete after six rounds (32–76 operations missing; the re-compilation
  guard rejects 8–10 style-violating or redefining emissions per trial);
  Linux 0/3 compiles (two further trials lost to endpoint empty-body
  failures, recorded as such). The honest reading, now in the paper: the
  bounded automated budgets alone do not reproduce the flagship; its
  recorded chain additionally used interactive compile repair, lowering
  rounds, dataflow repair, deterministic normalization, and the disclosed
  merge of duplicate lowering emissions. The bounded gate is a rejection
  instrument in practice.
- Trials are at temperature 0 on one (private) endpoint: they measure
  serving variance, not deliberate sampling diversity. Cross-driver
  repeated trials and public-model replication remain in the debt ledger.
- Rerun-round addition (cross-driver trials, op-count hypothesis): the
  same protocol was run on gpio-cadence (32 ops, loop-free) with three
  further deterministic normalizations added to the protocol after the
  first run exposed them (primitive stubs rewritten into a windowed
  backing array; stub `main()` completed from the formal module list,
  mirroring the recorded chain's scripted main append; missing
  `MODULE_LICENSE()` appended for the Linux module build). Harness
  result: 5/5 check-backed acceptance, 1/5 full strict-gate acceptance
  — one trial passed with zero repair rounds on its raw first pass —
  against 0/5 for DesignWare at either level. The rerun also exposed and
  fixed a measurement gap in the harness itself: the gate's
  runtime-trace field was only populated for the harness backend; it is
  now derived from the bare-metal callback/W1C-drain oracles and treated
  as not-applicable for the Linux module backend once it builds. Record:
  `research/experiments/results/gpio-cadence-repeated-trials.json`;
  paper §6 cross-driver paragraph. Public-model replication stays in the
  debt ledger.

  twelve fresh full-source generation attempts returned no usable fenced

  observation, and the pipeline-side repeated trials show bounded compile
  repair closing compilation for a constrained candidate in only 3/5
  bare-metal and 0/5 harness trials — no completed run compiles the
  unconstrained baseline candidate under any budget.

  (`qa/verification/existing_tool_comparison.py`, table in §6, inputs
