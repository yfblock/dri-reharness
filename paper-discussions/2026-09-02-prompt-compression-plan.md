# 提示词压缩方案：生成视图与审计视图分离

> 撰写日期：2026-09-02
> 依据版本：commit `f22ab7b` 之后（evidence 已改文本 RIS 注入）
> 触发问题：实测 LLM 输入在小驱动上不降反升（edu 2.3x、ftgpio 3.5x），与"契约只有设备核心所以 token 下降"的直觉相反
> 本文档记录病理解剖、压缩方案与待验证的效果问题。

---

## 1. 实测病理（ftgpio010，修正双重序列化误差后）

```
真实提示 ≈ 30.8k ch（模板 2.4k + 证据 JSON 12.3k + RIS 文本 16.1k）
源码      = 8.85k ch
比值      = 3.5x（输入反超）
```

### 证据 JSON（12,266 ch）——干净，基本不动

| 键 | ch | 占比 | 判定 |
|---|---|---|---|
| functions（角色/回调表） | 5,632 | 46% | 语义知识，保留 |
| framework（回调签名） | 3,794 | 31% | API 说明书，保留 |
| bind/registers/constants/resources | 2,191 | 18% | 操作性知识，保留 |
| 其它 | 285 | 2% | — |

77% 是意图层语义（模型写目标代码必需），不是冗余。

### RIS 文本（16,127 ch）——病灶所在

```
绝对路径出现 76 次 = 6,916 ch = RIS 的 43%（≈ 源码文件的 78%）
digest 每op一个   ≈ 1.5k ch
[Exact]/@op_id    少量
```

每个 op 形如：

```
gpio_initial_data := R(B4, g->base.GPIO_DATA_IN) -- DataTransfer @op_43 [Exact] digest=16d8… /home/…/gpio-ftgpio010.c:276
└─ 操作本体 ~50ch ─────────────────────────────┘                └────────── 审计后缀 ~150ch ──────────────┘
```

正式 JSON 更极端：路径 292 次 = 26,572 ch（21%），外加 14 个模块级
`source` 数组各重复一遍相对路径。

### 诊断结论

**证据契约在服务两个主人**：
- 审计（provenance：路径/行号/origin/reliability/digest——给验证门与人工审查）
- 生成（指令：op 本体 + 寄存器 + bind + 函数角色——给 LLM）

当前文本 RIS 把两份都喂给模型。LLM 不需要知道 `op_43 的证据来自哪个
绝对路径`——那是审计信息。

## 2. 压缩方案（生成视图手术）

1. **路径表化**：文件头声明一次 `file#1 = /abs/path`，op 尾只留 `#1:276`
   −6.9k ch（RIS 的 43%）
2. **digest 剥离**：digest 是 lowering 对账用的，生成不需要 → 移到审计视图
   −1.5k ch
3. **[Exact]/@op_id 精简**：op_id 保留（后端 prompt 引用 op），reliability
   标记在生成视图可省（它不改变生成的代码，只影响就绪判定）
4. **module.source 数组去重**：模块头部引用文件表编号
5. **（可选）模板瘦身**：2.4k 固定开销中重复的后端说明压缩

预期：ftgpio 提示 30.8k → ~21-22k ch（−30%），RIS 16.1k → ~8k（减半）。
ahci（已过交叉点 1.59x）进一步放大；dwc2 级多源驱动优势显著。

## 3. 待验证问题（worktree 实验）

- [ ] 压缩后提示实际下降多少？（edu/ftgpio/ahci 三点 + 交叉点位移）
- [ ] **效果有没有减弱？**——同样的模型与温度，压缩前 vs 压缩后：
      生成代码的编译通过率、receipt 覆盖率（每个 op 是否仍被实现）、
      trace 一致性是否变化。审计信息的缺失是否影响模型对 op 语义的理解
      （假设：不影响，因为 provenance 不是语义；但需实验证实）
- [ ] 行号保留与否的影响：`:276` 对模型是定位线索还是噪声？
      （对照组：完全去掉行号）

## 4. 正确的论文 claim 形态（无论实验结果如何）

- **不声称**"token 下降了 X%"——小驱动上为假
- **可声称**（若压缩实验通过）：*输入随设备核心缩放，不随胶水缩放*，
  配缩放曲线（op 数 vs 源码行数），交叉点在压缩后左移
- 与 RQ-c（约束收益对照）配对：token 不是收益本身，约束才是；
  token 缩放是大驱动上的副产品
