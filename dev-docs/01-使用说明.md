# 使用说明

本文面向第一次运行项目的开发者和 Agent。所有命令都假定当前目录是仓库根目录：

```bash
cd /home/yfblock/Code/dri-trans-paper/reharness
```

## 1. 环境要求

需要以下能力：

- Python 3，当前开发环境使用 Python 3.12。
- `clang.cindex` 和 libclang 18。
- GNU Make、GCC、内核模块构建所需的 host tools。
- `qemu-system-x86_64`，运行 QEMU profile 和确定性实验时需要。
- `cpio`、`gzip`、`timeout` 等 initramfs/QEMU 脚本依赖。
- 已初始化的 `vendor/linux` Git submodule。

基础检查：

```bash
python3 --version
python3 -c 'import clang.cindex; print(clang.cindex.Config.loaded or "libclang not loaded yet")'
qemu-system-x86_64 --version
make --version
```

如果只做 extractor 的静态分析，可以暂时不准备 QEMU；如果运行 Linux backend、Kbuild
或 profile matrix，则必须准备 pinned kernel。

## 2. 首次初始化

```bash
git submodule update --init

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-langgraph.txt

./tools/build/prepare_kernel.sh build
```

`requirements-langgraph.txt` 提供可选编排依赖：`langgraph`、`langchain-core` 和
`langchain-openai`。项目的基础 extractor 依赖和 libclang 由宿主环境提供。

AMBA 的 x86 synthetic compile-test 依赖 `platform/kernel/amba-compile-test.patch`。
`prepare_kernel.sh` 会在需要时应用它，然后使用
`platform/kernel/linux-x86_64.config` 构建 `platform/kernel/build`。

## 3. 公共入口

```bash
./run.sh help
```

`run.sh` 会自动设置：

```text
PYTHONPATH=src:qa:qa/verification
```

因此优先使用 `./run.sh ...`，不要直接从仓库根目录执行裸的
`python3 -m langgraph_workflow`，否则可能找不到 `src/` 下的模块。

主要命令：

| 命令 | 用途 |
| --- | --- |
| `extract` | 提取 RIS |
| `spec` | 推断 backend-independent DeviceSpec |
| `gen` | 生成一个 backend 候选 |
| `driver` | 执行完整确定性 pipeline |
| `langgraph` | 执行 LangGraph workflow |
| `auto-driver` | 自动识别 profile、生成 manifest 并运行一条输入 |
| `experiment` | 从 manifest 执行闭环实验 |
| `profile-matrix` | 运行通用 profile QEMU 矩阵 |
| `qemu-experiments` | 运行历史确定性 QEMU 实验 |
| `test` | 执行项目测试入口 |

## 4. 只做静态提取

```bash
./run.sh extract benchmarks/drivers/baseline/gpio-ftgpio010.c \
  artifacts/output/ftgpio.ris

./run.sh spec benchmarks/drivers/baseline/gpio-ftgpio010.c \
  artifacts/output/ftgpio.dspec

./run.sh facts benchmarks/drivers/baseline/gpio-ftgpio010.c
./run.sh metrics benchmarks/drivers/baseline/gpio-ftgpio010.c
./run.sh reliability benchmarks/drivers/baseline/gpio-ftgpio010.c
```

常见输出包括 `.ris`、`.dspec`、`.facts`、`.formal.json`、`.bind` 和
`generation-contract.json`。这些文件是后续生成和验证的输入证据，不是自动等价证明。

## 5. LangGraph workflow

### 5.1 Analysis 模式

analysis 不调用 LLM，只执行输入校验、profile/manifest 解析和 extractor evidence
生成：

```bash
./run.sh langgraph benchmarks/drivers/baseline/edu.c \
  --backend linux \
  --mode analysis
```

默认输出：`artifacts/langgraph/edu/`。也可以指定输出目录：

```bash
./run.sh langgraph benchmarks/drivers/baseline/edu.c \
  --mode analysis \
  --output-dir /tmp/reharness-edu-analysis
```

### 5.2 Generation 模式

generation 会调用配置的 LangChain model 生成候选，但没有 manifest 时无法证明完整
runtime：

```bash
./run.sh langgraph benchmarks/drivers/baseline/edu.c \
  --backend linux \
  --mode generation
```

候选仍须经过 generation contract 和 Kbuild gate；没有可信 runtime fixture 的输入
最终只能是 `inconclusive`，不能报告为完整成功。

### 5.3 Experiment 模式

experiment 必须提供 manifest，并会继续执行 ExperimentRunner、Kbuild、QEMU、
manifest-owned test 和 unload：

```bash
./run.sh langgraph benchmarks/drivers/baseline/edu.c \
  --backend linux \
  --experiment-manifest benchmarks/experiments/edu.json \
  --mode experiment
```

当前通用 profile fixture 示例：

```bash
./run.sh langgraph benchmarks/drivers/fixtures/reharness-amba-sensor.c \
  --backend linux \
  --experiment-manifest benchmarks/experiments/reharness-amba.json \
  --mode experiment
```

## 6. LangChain / OpenAI-compatible LLM 配置

默认 backend 是 LangChain。模型默认从 `.reharness/pi/models.json` 发现，当前项目
配置为 `gpt-5.6-luna` 和 `https://ai.yfblock.cn/v1`。API key 不应写入模型 metadata
或提交到 Git，只从环境变量或受信任的本地 auth 文件读取。

推荐显式设置：

```bash
export REHARNESS_LLM_MODEL=gpt-5.6-luna
export REHARNESS_LLM_BASE_URL=https://ai.yfblock.cn/v1
export REHARNESS_LLM_API_KEY='your-api-key'
export REHARNESS_LLM_BACKEND=langchain
export REHARNESS_LLM_TIMEOUT=600
export REHARNESS_LLM_TEMPERATURE=0
```

也支持 `OPENAI_API_KEY` 作为 key 的兼容环境变量。当前 bridge 使用
`langchain-openai` 的 `ChatOpenAI`，接收 OpenAI-compatible Chat Completions 风格
endpoint；Responses-only endpoint 需要先确认 `langchain-openai` 版本和服务端协议
兼容，不能仅根据模型名推断已支持。

配置好 key 后，使用 generation 或 experiment 命令；analysis 模式不会消耗模型额度。

## 7. Automatic driver

先 dry-run 查看 profile 识别和生成的 manifest：

```bash
./run.sh auto-driver \
  benchmarks/drivers/fixtures/reharness-i2c-sensor.c \
  --dry-run

./run.sh auto-driver qa/tests/fixtures/spi-client.json --dry-run
```

正式运行可以指定 backend、输出目录和 JSON 报告：

```bash
./run.sh auto-driver benchmarks/drivers/fixtures/reharness-i2c-sensor.c \
  --backend linux \
  --output-dir artifacts/auto-driver/i2c
```

输入可以是单个 C 文件、多源 descriptor JSON 或 schema-2 manifest。profile plugin
通过 `--profile-plugin` 注入：

```bash
./run.sh auto-driver path/to/driver.c \
  --profile-plugin path/to/profile_plugin.py \
  --dry-run
```

plugin profile 默认不进入无参数的 acceptance matrix，验证 plugin 时需要显式
manifest 或重复使用 `--required-profile PROFILE`。

## 8. Profile matrix 和 QEMU

准备内核后运行全部默认 required profiles：

```bash
./run.sh profile-matrix
```

指定输出目录：

```bash
./run.sh profile-matrix --output artifacts/profile-matrix-local
```

只运行一个 manifest：

```bash
./run.sh profile-matrix \
  --manifest benchmarks/experiments/reharness-amba.json \
  --output artifacts/profile-matrix-amba
```

只要求指定 profile：

```bash
./run.sh profile-matrix \
  --profile amba-generic \
  --required-profile amba-generic \
  --output artifacts/profile-matrix-amba
```

需要 trace matching 时：

```bash
./run.sh profile-matrix --require-trace
```

最终报告通常在 `artifacts/profile-matrix/matrix.json`。报告中：

- `accepted`：required profile 和其声明的 compile/runtime/test/unload 证据均通过；
- `failed`：有明确失败，例如 QEMU Oops、probe 失败、required test 失败或 unload 失败；
- `inconclusive`：证据或可信 fixture 缺失，不能安全推断成功。

不要把 `runtime-ready` inventory 行当作实际运行结果，必须查看 `matrix.json` 的
`results`、`failed_profiles` 和 `inconclusive_profiles`。

## 9. 测试

项目标准入口：

```bash
./run.sh test
```

profile runtime 当前的 focused suite：

```bash
PYTHONPATH=src:qa:qa/verification \
pytest -q qa/tests/test_profile_runtime.py \
  qa/tests/test_profile_matrix.py \
  qa/tests/test_driver_profiles.py
```

静态检查：

```bash
git diff --check
bash -n run.sh scripts/qemu/qemu_run.sh tools/build/prepare_kernel.sh
PYTHONPATH=src:qa:qa/verification \
  python3 -m py_compile qa/verification/run_profile_matrix.py
```

完整 pytest 可能会因为 vendored Linux selftest 被 pytest 收集、资源限制或冻结
artifact 与当前工作树不一致而失败。遇到这种情况，先阅读
[05-故障排查.md](05-故障排查.md)，不要把排除某个测试后的局部通过写成完整回归通过。

## 10. 确定性实验和论文复现

```bash
./run.sh qemu-experiments
python3 qa/verification/run_matrix.py
python3 qa/verification/run_multisource_matrix.py
python3 qa/verification/run_clock_model_boundary.py
python3 qa/verification/reliability_report.py \
  --output research/experiments/results/reliability.json
python3 tools/reporting/generate_paper_results.py
```

论文结果必须以 `research/experiments/results/` 下的机器报告为准，不要从某一次
LLM 输出或单个 QEMU 日志手工推断论文数字。
